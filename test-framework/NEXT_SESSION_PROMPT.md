Правила работы (я их задал, соблюдай):
1. Фазы: ветка → коммит → fast-forward в main → push. Коммит и push только после моего явного разрешения на фазу.
2. Приложение (app/) не меняй. Дефекты приложения оформляются как issue, исправляю их я сам по своему решению.
3. Тесты не подгоняй под текущее поведение приложения. Если ожидание верно, а приложение падает — тест остаётся красным. Хаки, которые маскируют дефекты (JS-обходы, скрытие элементов, проглатывание исключений), не добавляй.
4. Внешние действия — только с моим подтверждением: публикация отчётов, создание issue, dispatch workflow, изменения настроек репозитория и переменных.
5. Коммит-трейлер бери из системного напоминания своей сессии.
6. Если шаг требует правки вне test-framework, CI или корневых compose-файлов, сначала скажи мне, что и почему.
