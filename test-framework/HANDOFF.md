## 2. Как работали (правила, которые приняты с пользователем)

- Фазы: ветка → коммит → fast-forward в `main` → push. Ветку не оставляем висеть.
- Коммиты и push только по явному разрешению пользователя на фазу.
- **Приложение (`app/`) не менять.** Исправления дефектов приложения — отдельные issue, решает пользователь.
- Тесты не подгоняются под текущее поведение приложения. Если ожидание верно, а приложение падает — тест остаётся красным, это дефект.
- Не отключать хаки и проверки, которые маскируют дефекты, подменой ожиданий.
- Внешние действия (публикация в AWS, создание issue, dispatch workflow) — только с подтверждением.
- Коммит-трейлер: `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.
- GenAI не поднимаем (нужен ключ), записан в бэклог.

## 3. Аудит: что нашли (исходное состояние)

Тесты были сгенерированы другой LLM. Главные проблемы:

1. **Тесты подстраивались под приложение.** В `app/` были 7 коммитов «Fix…» — правки приложения ради тестов. Проверено на чистом стеке: на исходном коде E2E проходят. Откатили 6 из 7, `680e250` оставили (он даёт 404 на несуществующего владельца, что правильно). Коммит `850f771`.
2. **Ложные тесты.** `GatewayCircuitBreakerTest` проверял WireMock, а не шлюз. Удалён.
3. **Маскировка дефектов в Page Objects.** `noValidate`, `reportValidity`, удаление `pattern`/`required`, `setForce(true)`, скрытие чата через JS, ввод значений через `input` events, `catch (Exception ignored)` в ожиданиях. Всё убрано.
4. **Компонентные тесты проверяли DAO, а не сервисы.** Схема `init.sql` — правленая копия схемы приложения. Это пробел в покрытии, не недостаток архитектуры. Открыто.
5. **Инфраструктурные проблемы.** `Thread.sleep` в Page Objects, статические синглтоны БД, очистка данных только в конце теста (при падении мусор оставался), `mvn` не в PATH на машине, JDK 17 по умолчанию.
6. **Даты.** Сервисы отдают даты в разных форматах (см. issue #3), фронтенд показывает на день раньше в западных часовых поясах (issue #2).

## 5. Как поднять полный локальный стек

Рабочая схема — `docker-compose.test.yml` плюс override с недостающими сервисами (admin, tracing, Prometheus, Grafana). Override сейчас лежит во временной папке, **его надо перенести в репозиторий**: файл `full-stack.override.yml` в scratchpad сессии, пути в нём абсолютные (`C:/Users/root/IdeaProjects/petclinic/app/docker/...`).

Команды (из корня репозитория):
```
docker compose -f docker-compose.test.yml down -v
cd app && ./mvnw -B -q clean package -DskipTests spring-boot:repackage -pl spring-petclinic-customers-service,spring-petclinic-api-gateway -am
cd .. && docker compose -f docker-compose.test.yml -f <override> up -d --build
```
Порты: API 8080, customers 8081, visits 8082, vets 8083, Eureka 8761, config 8888, admin 9090, Prometheus 9091, Grafana 3030, Zipkin 9411, MySQL 3306.

Известные особенности:
- `visits-service` может упасть на первом старте (нет таблицы `pets`): `docker compose ... up -d visits-service`.
- Регистрация в Eureka идёт с задержкой 30–60 с; до этого шлюз отвечает без visits.
- Счётчики БД после тестов должны совпадать с seed (10 владельцев, 13 питомцев). Если нет — остался мусор.

Запуск тестов: `cd test-framework && ./mvnw -B test -pl e2e-tests` (или `mvnw.cmd` в PowerShell). Подмножество: `-Dgroups=smoke`, `-Dgroups=negative`, `"-Dgroups=!known-defect"` (в PowerShell параметр с `!` и `=` берём в кавычки).

## 6. Дефекты приложения (открытые issue)

- **#1** Плавающий чат перехватывает клик «Add Visit» на странице владельца. Чат можно свернуть кнопкой «Chat with Us!» — это важно для исправления.
- **#2** Фронтенд: даты на день раньше в западных часовых поясах (`utils/dates.js`). Проверено через `Intl`: Нью-Йорк показывает 6 вместо 7.
- **#3** API: дата питомца приходит как UTC-datetime (`2000-09-07T00:00:00.000Z`), дата визита как `yyyy-MM-dd`. Причина: нет `@JsonFormat` у `Pet.birthDate` в customers-service. Гипотеза про `TZ` JVM не проверена.
- **#4** Визит к несуществующему питомцу → 500, нарушение внешнего ключа `visits_ibfk_1` не обрабатывается. Ожидается 404.
- **#5** Питомец с несуществующим `typeId` → 500, тип не проверяется, `NullPointerException` в `Pet.toString()`. Ожидается 400.

Не заведено как issue, есть в бэклоге: пустое описание визита принимается (201), хотя UI требует описание; дубликаты телефона принимаются.
